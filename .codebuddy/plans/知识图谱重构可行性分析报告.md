## 一、执行摘要

### 1.1 核心结论

**推荐采用「混合模式」渐进重构**，而非完全图谱化。

| 指标       | 评估                             |
| ---------- | -------------------------------- |
| 技术可行性 | ✅ 高 - 现有图谱基础设施完善     |
| 改动范围   | ⚠️ 中 - 涉及 29+ 文件            |
| 风险等级   | ⚠️ 中 - 需要数据迁移和兼容性处理 |
| 实施周期   | 📅 2-3 周                        |

### 1.2 关键发现

1. **现有图谱系统已相当完善**
   - Neo4j 图数据库已部署
   - Character/WorldSetting/Event/Chapter/PlotNode/Echo 节点类型已实现
   - AI 关系提取 (`graphLlm.extractCharacterRelationships`) 已工作
   - 三元组同步机制 (`syncProjectToGraph`) 已运行

2. **Character.relationships 是核心痛点**
   - 当前为 string 类型（如 `"朋友: 张三；敌人: 李四"`）
   - 无法直接用于图谱查询
   - 需要 AI 二次解析，存在精度问题

3. **新字段未被充分利用**
   - `signature`, `desire`, `fear`, `contrast`, `weakness`, `tags`, `alignment` 已定义但代码未使用
   - AI 会生成这些字段，但前端不展示、业务逻辑不处理

### 2.1 评估矩阵

| 类型              | 当前图谱支持       | 关系字段                                                               | 属性字段                                  | 图谱适配度 | 优先级 |

| **Echo**          | ✅ 节点            | targetId, triples[], branchId                                          | id, description, status, confidence       | ⭐⭐⭐ 高  | P1     |

### 2.2 字段分类

**关系型字段（可迁图谱）**:

- Character.relationships → 角色间关系边
- PlotNode.relatedCharacters[] → 情节-角色关联
- PlotNode.relatedLocations[] → 情节-地点关联
- PlotNode.conflictScenario.participants[] → 冲突参与者
- Echo.triples[] → 状态变更三元组
- TimelineEvent.involvedEntities[] → 事件参与实体

**属性型字段（保留实体）**:

- Character: id, name, role, archetype, description, alignment, tags, desire, fear, signature, contrast, weakness
- WorldSetting: id, title, category, content
- PlotNode: id, title, content, beatTag, order
- Chapter: id, title, content, summary, order

```typescript
updateProject(data) {
  // 1. 更新本地状态
  set({ project: { ...state.project, ...data } });

  // 3. 触发自动保存
```
