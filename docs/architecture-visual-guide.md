## 2. AI调用流程对比

### 普通版流程

```
用户操作
   ↓
组件调用AI服务
   ↓
AICallInterceptor.interceptCall()
   ↓
检查功能开关：callConfirmation = false
   ↓
直接返回 { approved: true }
   ↓
执行AI调用
   ↓
返回结果
```

### 高级版流程

```
用户操作
   ↓
组件调用AI服务
   ↓
AICallInterceptor.interceptCall()
   ↓
检查功能开关：callConfirmation = true
   ↓
触发 'ai-call-intercepted' 事件
   ↓
显示AICallConfirmDialog
   ├─ 用户查看prompt
   ├─ 可选：编辑prompt
   └─ 用户确认/取消
   ↓
返回 { approved: true/false, modifiedPrompt }
   ↓
如果approved:
   ├─ 使用modifiedPrompt（如有）
   ├─ 执行AI调用
   └─ 记录调用历史
如果rejected:
   └─ 抛出错误，终止调用
```

## 4. 错误隔离机制

```
┌──────────────────────────────────────────────────────────────┐
│                     应用根组件                                │
│                  FeatureFlagProvider                         │
└──────────────────────────────────────────────────────────────┘
                          ↓
        ┌─────────────────┴─────────────────┐
        │                                   │
   普通版组件                          高级版组件
        │                                   │
        │                        ┌──────────┴──────────┐
        │                        │ PremiumFeatureBoundary │
        │                        └──────────┬──────────┘
        │                                   │
        │                          ┌───────┴────────┐
        │                          │                │
        │                      正常运行          发生错误
        │                          │                │
        │                          ↓                ↓
        │                      渲染UI          捕获错误
        │                                          │
        │                                          ↓
        │                                     显示Fallback
        │                                     (不影响普通版)
        │
        └──────────────────────────────────────────┐
                                                   ↓
                                        应用继续正常运行
                                     (普通版不受高级版错误影响)
```

## 7. 配置优先级与合并策略

```
DEFAULT_CONFIG (默认配置)
   ↓
+ savedConfig (用户保存的配置)
   ↓
= mergedConfig (合并后的配置)
   ↓
应用到 FeatureFlagService
   ↓
根据 tier (FREE | PREMIUM) 确定功能开关
   ↓
组件通过 useFeatureFlags() 访问
```

**合并规则**：

- 深度合并（deepMerge）
- 用户配置优先于默认配置
- 保持配置结构的完整性

## 8. 性能优化策略

```
┌──────────────────────────────────────────────┐
│            初始加载                           │
│  • FeatureFlagService 初始化 (轻量级)        │
│  • 只加载必要配置                             │
└──────────────────────────────────────────────┘
                   ↓
┌──────────────────────────────────────────────┐
│         普通版用户                            │
│  • 不加载高级版组件代码                       │
│  • 不加载高级版配置                           │
│  • 最小化初始bundle大小                      │
└──────────────────────────────────────────────┘
                   ↓
┌──────────────────────────────────────────────┐
│         高级版用户                            │
│  • 懒加载高级版组件 (React.lazy)             │
│  • 按需加载自定义prompts                     │
│  • 动态导入大型依赖                           │
└──────────────────────────────────────────────┘
                   ↓
┌──────────────────────────────────────────────┐
│         运行时优化                            │
│  • 条件渲染避免不必要的组件                  │
│  • 错误边界隔离防止重渲染                    │
│  • 缓存功能开关状态                          │
└──────────────────────────────────────────────┘
```

## 总结

这套架构通过清晰的层次划分和职责分离，实现了：

✅ **完全隔离**：普通版和高级版代码、配置、数据完全分离
✅ **灵活扩展**：易于添加新的高级功能，不影响现有代码
✅ **性能优化**：懒加载、条件渲染、代码分割
✅ **安全可靠**：错误边界、权限验证、降级策略
✅ **易于维护**：清晰的依赖关系、完善的文档、示例代码
