# 键盘导航和可访问性测试指南

## 📋 概述

本文档提供了 Muse 小说架构师应用的完整键盘导航和可访问性测试指南。

## 🎯 测试目标

确保应用符合 WCAG 2.1 AA 级标准，包括：
- ✅ 键盘可访问性
- ✅ 焦点管理和可见性
- ✅ 屏幕阅读器兼容性
- ✅ ARIA 属性正确性
- ✅ 键盘焦点陷阱（模态框）

## ⌨️ 键盘导航测试

### 1. 基础导航测试

#### 测试步骤：
1. 启动应用
2. 确保鼠标未使用
3. 仅使用键盘进行以下操作：

#### 测试用例：

**Tab 键导航**
- [ ] 使用 Tab 键可以遍历所有交互元素
- [ ] 焦点顺序符合逻辑（从上到下，从左到右）
- [ ] 当前焦点元素有明显的视觉指示（紫色边框）
- [ ] Shift+Tab 可以反向导航

**侧边栏导航**
- [ ] Tab 到侧边栏时，聚焦在当前活动项
- [ ] 使用 Enter/Space 可以激活导航项
- [ ] 使用方向键可以在导航项之间移动
- [ ] ESC 键可以收起展开的侧边栏
- [ ] 焦点不会丢失（无焦点陷阱）

**模态框导航**
- [ ] 模态框打开时，焦点自动移入模态框
- [ ] Tab 键只在模态框内循环（焦点陷阱）
- [ ] ESC 键可以关闭模态框
- [ ] 模态框关闭后，焦点返回触发元素

**表单导航**
- [ ] Tab 可以遍历所有表单字段
- [ ] 表单验证错误有明确的键盘可访问提示
- [ ] 错误字段可以轻松聚焦和修复

### 2. 功能快捷键测试

| 快捷键 | 功能 | 测试状态 |
|--------|------|----------|
| `Tab` | 下一个元素 | ⬜ 通过 / ❌ 失败 |
| `Shift + Tab` | 上一个元素 | ⬜ 通过 / ❌ 失败 |
| `Enter` | 激活按钮/链接 | ⬜ 通过 / ❌ 失败 |
| `Space` | 激活按钮/切换 | ⬜ 通过 / ❌ 失败 |
| `Escape` | 关闭模态框/取消操作 | ⬜ 通过 / ❌ 失败 |
| `Arrow Keys` | 在列表中导航 | ⬜ 通过 / ❌ 失败 |
| `Home` | 跳到列表开头 | ⬜ 通过 / ❌ 失败 |
| `End` | 跳到列表末尾 | ⬜ 通过 / ❌ 失败 |

### 3. 焦点可见性测试

**视觉检查**
- [ ] 焦点元素有明显的 2px 紫色边框（#8b5cf6）
- [ ] 边框有 2px 的偏移量，确保可见
- [ ] 焦点指示器在所有背景下都清晰可见
- [ ] 焦点指示器不会被裁剪或遮挡

**测试不同组件**
- [ ] 按钮焦点可见
- [ ] 链接焦点可见
- [ ] 输入框焦点可见
- [ ] 下拉菜单焦点可见
- [ ] 模态框内元素焦点可见

## 🔍 屏幕阅读器测试

### 1. NVDA (Windows) 测试

**安装和设置**
1. 下载 NVDA: https://www.nvaccess.org/
2. 安装并启动 NVDA
3. 使用默认设置

**测试清单**
- [ ] 页面标题正确播报
- [ ] Skip Link "跳到主内容" 可访问并工作
- [ ] 侧边栏播报为 "主导航"
- [ ] 每个导航项有明确的标签（如 "创世纪 Genesis"）
- [ ] 当前活动项播报为 "当前页"
- [ ] 模态框打开时有通知
- [ ] 表单错误有适当的 ARIA 提示
- [ ] 动态内容变化有通知（aria-live）

### 2. VoiceOver (macOS) 测试

**激活 VoiceOver**
1. 按 `Cmd + F5` 激活 VoiceOver
2. 使用 VoiceOver 实用工具进行设置

**测试清单**
- [ ] 使用 `VO + →` 导航页面
- [ ] 使用 `VO + Space` 激活元素
- [ ] 检查所有交互元素有标签
- [ ] 检查模态框焦点管理

### 3. JAWS 测试（可选）

**测试清单**
- [ ] 使用 JAWS 的虚拟光标导航
- [ ] 测试表单访问
- [ ] 测试模式切换

## 🎨 ARIA 属性验证

### 1. 使用浏览器开发工具

**Firefox Accessibility Inspector**
1. 按 `F12` 打开开发者工具
2. 点击 "Accessibility" 标签
3. 检查每个交互元素的 ARIA 属性

**Chrome Accessibility Tree**
1. 按 `F12` 打开开发者工具
2. 在 Elements 面板中，点击 "Accessibility" 侧边栏
3. 检查 ARIA 属性和可访问名称

### 2. ARIA 属性检查清单

**导航区域**
- [ ] `<nav>` 元素有 `aria-label="主导航"`
- [ ] 按钮有 `aria-label` 或文本内容
- [ ] 当前页有 `aria-current="page"`

**模态框**
- [ ] 有 `role="dialog"`
- [ ] 有 `aria-modal="true"`
- [ ] 有 `aria-labelledby` 指向标题
- [ ] 打开时焦点移入
- [ ] 关闭时焦点返回

**表单**
- [ ] 输入框有关联的 `<label>`
- [ ] 错误消息有 `aria-describedby`
- [ ] 必填字段有 `aria-required="true"`
- [ ] 无效字段有 `aria-invalid="true"`

**动态内容**
- [ ] 状态更新使用 `aria-live="polite"`
- [ ] 重要通知使用 `aria-live="assertive"`

## 🛠️ 自动化测试工具

### 1. Lighthouse 可访问性审计

**运行 Lighthouse**
1. 打开 Chrome DevTools (F12)
2. 点击 "Lighthouse" 标签
3. 选择 "Accessibility"
4. 点击 "Analyze page load"

**目标分数**
- [ ] 可访问性分数 > 90
- [ ] 无 "Focus not managed" 问题
- [ ] 无 "ARIA labels" 问题
- [ ] 无 "Color contrast" 问题

### 2. axe DevTools

**安装和使用**
1. 安装 axe DevTools 扩展
2. 点击扩展图标
3. 选择 "Scan ALL of my page"
4. 查看报告

**期望结果**
- [ ] 无严重 (Serious) 问题
- [ ] 无关键 (Critical) 问题
- [ ] 适度 (Moderate) 问题尽可能少

### 3. WAVE 浏览器扩展

**测试步骤**
1. 安装 WAVE 扩展
2. 点击扩展图标
3. 查看页面上的覆盖层

**检查清单**
- [ ] 无红色错误图标
- [ ] 无黄色警告图标（或尽可能少）
- [ ] 所有交互元素有标签
- [ ] 对比度符合标准

## 🎯 WCAG 2.1 AA 合规性检查

### 1. 可感知性 (Perceivable)

**文本替代**
- [ ] 所有图像有 `alt` 文本
- [ ] 图标按钮有 `aria-label`
- [ ] 装饰性图标有 `aria-hidden="true"`

**时基媒体**
- [ ] 无自动播放音频/视频（或可停止）
- [ ] 有字幕（如适用）

**可适应性**
- [ ] 响应式设计在不同设备上工作
- [ ] 横向滚动可用（如需要）

**可区分性**
- [ ] 文本对比度 ≥ 4.5:1
- [ ] 大文本对比度 ≥ 3:1
- [ ] 非文本对比度 ≥ 3:1
- [ ] 焦点指示器可见

### 2. 可操作性 (Operable)

**键盘可访问**
- [ ] 所有功能可通过键盘访问
- [ ] 无键盘陷阱
- [ ] 键盘焦点不丢失

**足够时间**
- [ ] 无时间限制（或可延长时间）
- [ ] 自动滚动可暂停/停止/隐藏

**癫痫和身体反应**
- [ ] 无闪烁内容（>3次/秒）
- [ ] 单次闪烁不触发癫痫

**导航性**
- [ ] Skip Link 可用
- [ ] 页面有标题
- [ ] 焦点顺序逻辑
- [ ] 链接用途明确

### 3. 可理解性 (Understandable)

**可读性**
- [ ] 语言声明（`lang="zh-CN"`）
- [ ] 术语一致

**可预测性**
- [ ] 焦点变化不引起上下文变化
- [ ] 输入有清晰标签

**输入辅助**
- [ ] 错误识别和描述
- [ ] 错误更正建议
- [ ] 表单验证

### 4. 健壮性 (Robust)

**兼容性**
- [ ] 有效 HTML
- [ ] ARIA 属性正确使用
- [ ] 无弃用功能
