## 二、数据结构审查

### Prisma Schema (9个模型)

| 模型          | 用途         | 关系             |
| ------------- | ------------ | ---------------- |
| Project       | 项目主表     | 1:N → 所有子实体 |
| Character     | 角色数据     | N:1 → Project    |
| WorldSetting  | 世界观设定   | N:1 → Project    |
| PlotNode      | 情节节点     | N:1 → Project    |
| Chapter       | 章节         | N:1 → Project    |
| Echo          | 状态变更记录 | N:1 → Project    |
| Draft         | 草稿         | N:1 → Project    |
| PlotVersion   | 情节版本历史 | N:1 → Project    |
| TimelineEvent | 时间线事件   | N:1 → Project    |

### 前端类型定义 (types.ts)

- **ProjectState**: 全局项目状态接口
- **Character**: 包含 `structuredRelations` 新字段
- **CharacterRelation**: 关系类型枚举 (ENEMY_OF, ALLY_OF, LOVES 等)
- **CharacterArc**: 角色弧线 (救赎/堕落/坚守/觉醒)
- **KnowledgeTriple**: 知识三元组

### 数据一致性风险

| 风险     | 描述                                          | 严重程度 |
| -------- | --------------------------------------------- | -------- |
| 双写问题 | `relationships` 和 `structuredRelations` 字段 | 高       |
| 类型分散 | types.ts 和 schemas.ts 有重复定义             | 低       |
| 图谱同步 | 异步fire-and-forget，可能丢失                 | 中       |

## 三、后端API审查

### 项目API (projects.ts) - 12个端点

| 端点                                     | 方法   | 功能             | 风险评估     |
| ---------------------------------------- | ------ | ---------------- | ------------ |
| `/api/projects`                          | GET    | 获取项目列表     | 无分页       |
| `/api/projects/:id`                      | GET    | 获取项目详情     | OK           |
| `/api/projects/:id/chapters/:chapterId`  | GET    | 获取单章节       | OK           |
| `/api/projects/:id/chapters-content`     | GET    | 获取所有章节内容 | OK           |
| `/api/projects`                          | POST   | 创建项目         | OK           |
| `/api/projects/:id/full`                 | PUT    | **全量同步**     | **并发风险** |
| `/api/projects/:id`                      | PATCH  | 增量更新         | OK           |
| `/api/projects/:id`                      | DELETE | 删除项目         | OK           |
| `/api/projects/:id/echoes/batch-accept`  | POST   | 批量接受Echo     | OK           |
| `/api/projects/:id/echoes/batch-reject`  | POST   | 批量拒绝Echo     | OK           |
| `/api/projects/:id/echoes/undo-batch`    | POST   | 撤销批量操作     | OK           |
| `/api/projects/:id/echoes/batch-history` | GET    | 批量操作历史     | OK           |

### 全量同步风险分析 (PUT /full)

```
当前策略: DELETE-THEN-INSERT
风险:
1. 并发写入可能导致数据丢失
2. 事务失败后无法回滚已删除的数据
3. 大数据量时性能差

建议改进:
1. 使用 UPSERT 替代 DELETE-INSERT
2. 添加乐观锁机制
3. 实现增量同步策略
```

## 六、架构优势

1. **清晰的分层架构**: 前端组件层、服务层、状态管理层分离明确
2. **灵活的存储策略**: 支持IndexedDB本地存储和MySQL后端存储双模式
3. **图谱增强**: Neo4j图谱提供了强大的关系查询和推理能力
4. **AI集成良好**: 支持多AI提供商，有完善的任务路由机制
5. **类型安全**: TypeScript + Zod双重类型验证
6. **状态管理高效**: Zustand切片化订阅避免不必要重渲染
7. **离线支持**: IndexedDB允许无网络环境使用
