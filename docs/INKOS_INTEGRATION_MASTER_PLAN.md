## 一、项目背景

### 1.1 两个项目定位

| 项目 | 类型 | 核心价值 | 目标用户 |
|------|------|---------|---------|
| **Muse (主项目)** | Web 应用 | 可视化创作工作台 | 需要系统性规划的创作者 |
| **inkos** | CLI 工具 | 自动化小说生产管线 | 技术型创作者、批量生产者 |

### 1.2 整合动机

1. **功能高度互补**: Muse 擅长可视化构思，inkos 擅长自动化生产
2. **用户场景串联**: 形成"构思→生产→审阅"完整闭环
3. **差异化体验**: GUI（创意探索）+ CLI（批量生产）双形态

---

## 二、inkos 核心能力

### 2.1 五 Agent 协作管线

```
Radar (趋势扫描) → Architect (规划) → Writer (写作) → Auditor (审计) → Reviser (修订)
```

### 2.2 独特价值

| 能力 | 描述 |
|------|------|
| **33 维度审计** | 连续性检查，确保内容一致 |
| **7 Truth Files** | 长期记忆系统，状态追踪 |
| **去 AI 味处理** | 降低 AIGC 检测风险 |
| **文风仿写** | 学习并注入特定作者风格 |
| **守护进程** | 无人值守持续写作 |
| **EPUB 导出** | 多格式输出支持 |

## 五、实施计划

### Phase 1: 数据格式互通 (2-3 天)

| 任务 | 描述 | 优先级 |
|------|------|--------|
| Zod 版本统一 | inkos 升级到 zod v4 | P0 |
| 类型映射定义 | ProjectState ↔ Truth Files | P0 |
| 导入命令 | inkos import muse | P1 |
| 导出功能 | Muse "导出到 inkos" | P1 |

### Phase 2: 工作流串联 (4-5 天)

| 任务 | 描述 | 优先级 |
|------|------|--------|
| 后端集成 | 引入 @actalk/inkos-core | P0 |
| API 端点 | /api/inkos/* 路由 | P0 |
| SSE 推送 | 流式进度反馈 | P1 |
| StorageAdapter | 数据存储抽象层 | P1 |

### Phase 3: 深度整合 (5-7 天)

| 任务 | 描述 | 优先级 |
|------|------|--------|
| 任务队列 | BullMQ 后台任务 | P2 |
| WebSocket | 双向实时通信 | P2 |
| 前端 UI | 创作工作台界面 | P2 |
| LLM 统一 | 多 Provider 支持 | P2 |

## 六、关键依赖

### 6.1 版本冲突

| 依赖 | inkos | Muse | 解决方案 |
|------|-------|------|---------|
| zod | 3.24.0 | 4.3.6 | 升级 inkos |
| LLM SDK | openai/anthropic | @google/genai | 适配层抽象 |

### 6.2 存储差异

| 系统 | inkos | Muse |
|------|-------|------|
| 主存储 | 文件系统 (Markdown) | IndexedDB |
| 图数据 | - | Neo4j |
| 同步策略 | Truth Files | ProjectState |

## 七、风险与对策

| 风险 | 概率 | 对策 |
|------|------|------|
