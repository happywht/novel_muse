# 安全检查清单

## 部署前安全检查

### 环境配置
- [ ] `.env` 文件已添加到 `.gitignore`
- [ ] 生产环境配置了 `NODE_ENV=production`
- [ ] 生产环境配置了强随机的 `API_KEYS`
- [ ] 没有在代码中硬编码任何密钥或密码
- [ ] 敏感配置（数据库密码、API 密钥）仅存在于 `.env` 文件中

### API Key 管理
- [ ] 使用 `npm run generate-key` 生成了安全的 API Keys
- [ ] 为不同的客户端/服务分配了不同的 API Keys
- [ ] API Keys 定期轮换（建议每 90 天）
- [ ] 有 API Key 泄露时立即撤销并更换的流程

### 认证配置
- [ ] 生产环境 `SKIP_AUTH=false`
- [ ] 生产环境已配置 `API_KEYS`（不能为空）
- [ ] 健康检查端点 (`/api/health`) 是唯一的公开路由
- [ ] 所有敏感 API 端点都需要认证

### 网络安全
- [ ] 生产环境使用 HTTPS
- [ ] 配置了适当的 CORS 策略
- [ ] 限制 API 请求大小（已设置 `limit: '50mb'`）
- [ ] 考虑添加速率限制（可选启用 `authRateLimit`）

### 监控与日志
- [ ] 启用了安全审计日志
- [ ] 监控失败的认证尝试
- [ ] 设置了异常访问模式告警
- [ ] 定期检查服务器日志

### 数据库安全
- [ ] 数据库连接使用加密连接
- [ ] 数据库用户权限遵循最小权限原则
- [ ] 定期备份数据库
- [ ] 敏感数据已加密存储

## 定期安全审查（每月）

### 访问控制审查
- [ ] 审查活跃的 API Keys
- [ ] 移除不再使用的 API Keys
- [ ] 检查用户权限和角色分配

### 依赖安全
- [ ] 运行 `npm audit` 检查依赖漏洞
- [ ] 更新有安全漏洞的依赖包
- [ ] 检查是否有废弃的依赖

### 日志审查
- [ ] 检查认证失败日志
- [ ] 审查异常访问模式
- [ ] 检查错误日志中的安全相关信息

## 事件响应

### API Key 泄露
1. 立即从 `API_KEYS` 中移除泄露的密钥
2. 生成新的 API Key
3. 通知相关客户端更新密钥
4. 审查使用泄露密钥的访问日志

### 未授权访问检测
1. 检查服务器日志确定访问范围
2. 审查受影响的数据
3. 必要时更换所有 API Keys
4. 加强监控和告警

## 合规性检查

### 数据保护
- [ ] 确认数据处理符合 GDPR/相关法规要求
- [ ] 用户数据访问和删除请求流程
- [ ] 数据保留政策已实施

### 审计
- [ ] 保留安全审计日志（至少 90 天）
- [ ] 定期进行安全评估
- [ ] 文档化安全事件和响应措施

## 开发环境安全

- [ ] 开发环境使用不同的 API Keys
- [ ] 开发数据库不包含生产数据
- [ ] 开发环境配置了适当的访问控制
- [ ] 团队成员了解安全最佳实践
